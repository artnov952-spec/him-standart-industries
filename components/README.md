# Client component contract

All authored components are React client components, use normal links and local SVG icons from `lucide-react` at 20px / 1.5 stroke.

- `StoreProvider` wraps root body. `useStore()` exposes `items`, `hydrated`, `count` (total units), `toast`, `addItem`, `setQuantity`, `removeItem`, `clearCart`. Cart schema `{productId,packaging,quantity}` is versioned in `him-standart-cart-v1`; invalid saved products/packages are discarded. LocalStorage hydration does not mismatch server HTML. Store toast uses `store-toast-region`, `store-toast`, close `icon-button`.
- `HeaderActions` renders `header-actions`, `header-cart`, `header-cart-count`, `mobile-menu-toggle`, `mobile-navigation`. Parent CSS hides mobile toggle on desktop. Escape closes mobile menu.
- `ProductCard({product})`: `.product-card`, `.product-image`, `.product-image-caption`, `.product-image-arrow`, `.product-body`, `.product-meta`, `.product-description`, `.product-specs`, `.product-review-link`, `.product-actions`, `.product-price`, `.product-availability`. It fetches approved review summary and never invents ratings.
- `CatalogClient({initialQuery?, initialCategory?, initialGrade?})`: `.catalog-search`, `.catalog-layout`, `.catalog-sidebar`, `.catalog-sidebar.is-open`, `.catalog-mobile-close`, `.catalog-categories`, `.catalog-count`, `.catalog-filter`, `.catalog-reset`, `.catalog-sidebar-help`, `.catalog-mobile-apply`, `.catalog-backdrop`, `.catalog-results`, `.catalog-toolbar`, `.catalog-filter-toggle`, `.catalog-result-count`, `.catalog-sort`, `.catalog-view`, `.catalog-grid`, `.catalog-grid.is-list`, `.catalog-empty`, `.catalog-bottom-note`. Filters query name/SKU/CAS/formula, category, grade. URL `q/category/grade` is preserved. Parent CSS: sidebar and backdrop behave as a mobile drawer; controls `catalog-mobile-*` hidden on desktop; use `.catalog-grid.is-list` to restyle cards horizontally if desired.
- `PurchaseControls({product})`: `purchase-controls`, `purchase-packaging`, `purchase-packaging-options`, `is-selected`, `purchase-quantity-label`, `purchase-row`, `quantity-control`, `field-hint`.
- `CartClient`: `cart-layout`, `cart-items`, `cart-items-heading`, `cart-item`, `cart-item-image`, `cart-item-info`, `cart-item-name`, `cart-item-meta`, `cart-packaging`, `cart-item-controls`, `quantity-control`, `cart-item-remove`, `cart-continue`, `cart-clear-confirm`, `cart-request`, `request-form`, `form-grid`, `form-full`, `form-consent`, `form-error`, `field-hint`, `honeypot`, `demo-notice`, `cart-success`, `cart-empty`, `cart-loading`.
- `Reviews({subject})`: subject product id or `company`. `reviews-section`, `reviews-heading`, `reviews-total`, `reviews-layout`, `reviews-summary`, `reviews-average`, `review-stars`, `reviews-distribution`, `reviews-track`, `reviews-main`, `reviews-list`, `review`, `review-heading`, `review-text`, `review-form`, `review-rating`, `review-rating-options`, `review-form-bottom`, `review-success`. Same common form classes as cart. Real public reviews only; a saved review stays pending and does not change public count.
- `InquiryForm({title?})`: contact/specification request without catalog items, requires comment >= 10 characters. Same request/form classes as cart. Uses same `/api/requests` endpoint with empty items and stable idempotency identifier. Server must allow this agreed case.

Common primitives parent CSS must provide: `button`, `button-dark`, `text-button`, `icon-button`, `sr-only`, `honeypot`, form controls/labels and minimum touch targets. No gradients, glow, glass, emojis, hardcoded fake ratings or prices.

POST request and review identifiers remain stable for a retry of unchanged content. Changed content gets a new request id; a successful save clears only the relevant draft. No Telegram success is claimed.
